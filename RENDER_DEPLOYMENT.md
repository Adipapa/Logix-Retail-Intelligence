# Render deployment — Logix Retail Intelligence

The `render.yaml` Blueprint deploys the complete platform from the `postgres-migration` branch:

- **Frontend:** Render Static Site, built with Vite and published from `dist`.
- **API:** Render Python Web Service running FastAPI/Uvicorn.
- **Database:** Managed Render PostgreSQL in Frankfurt.
- **Dropbox:** The API service runs the 15-minute inventory scheduler and imports up to 50 pending workbooks per run.

## Create the Render services

1. Sign in to Render and connect the GitHub account that can access `Adipapa/Logix-Retail-Intelligence`.
2. Choose **New → Blueprint**.
3. Select this repository and the `postgres-migration` branch. The Blueprint file is `render.yaml` at the repository root.
4. Review the three resources before applying the Blueprint:
   - `logix-retail-api`
   - `logix-retail-frontend`
   - `logix-retail-db`
5. Complete the prompted secret values. Do not commit them to GitHub.

The API is deliberately configured on a paid always-on Starter compute plan. A free web service can sleep after inactivity, which would interrupt the in-process 15-minute scheduler. The PostgreSQL service is configured on the smallest paid 256 MB plan. Current listed starting prices are approximately **US$7/month for the API and US$6/month for PostgreSQL**; the static site is free. Storage beyond the included amount, bandwidth, taxes, and future plan changes can add cost. Confirm the current Render price before applying.

## Required environment values

Set these on `logix-retail-api` in Render:

| Variable | Value |
| --- | --- |
| `APP_ENV` | `production` (set by Blueprint) |
| `DATABASE_URL` | Supplied from the managed Render database |
| `SECRET_KEY` | Generated by Render |
| `BOOTSTRAP_ADMIN_EMAIL` | The initial central administrator's email |
| `BOOTSTRAP_ADMIN_PASSWORD` | A strong, unique initial administrator password |
| `BOOTSTRAP_ADMIN_NAME` | Administrator's display name |
| `DROPBOX_REFRESH_TOKEN` | Dropbox OAuth refresh token |
| `DROPBOX_APP_KEY` | Dropbox app key |
| `DROPBOX_APP_SECRET` | Dropbox app secret |
| `DROPBOX_ROOT_PATH` | `/Logix Retail` |
| `CORS_ORIGINS` | The exact public frontend origin |

The Blueprint sets the expected frontend origin to `https://logix-retail-frontend.onrender.com`. After the first sync, check the actual static-site URL in Render. If Render assigned a different hostname or you add a custom domain, update `CORS_ORIGINS` on the API to the exact frontend origin and redeploy the API.

The frontend receives `VITE_API_URL` from the API service's `RENDER_EXTERNAL_URL` during its build. Do not put database credentials, Dropbox credentials, or the JWT secret in any `VITE_*` variable.

## Database migrations and first administrator

The API service runs `alembic upgrade head` as its pre-deploy command before starting Uvicorn. The application does not use `create_all` in production. The initial migration creates the registered SQLAlchemy models.

The bootstrap administrator is created when both bootstrap email and password are configured and that email does not already exist. Changing the bootstrap variables later does not reset an existing account's password.

## Dropbox import behaviour

Dropbox scanning is recursive under the configured root. Only Excel workbooks inside station folders are accepted; root-level files, `Cleanup` paths, and Dropbox conflicted copies are excluded. Manual sync and the 15-minute scheduled run each process up to 50 pending workbooks. Any remaining pending files remain queued for subsequent runs.

The current extraction support is template-dependent. A successful raw import does not mean every workbook has been mapped into dashboard KPIs; review extraction warnings and unmapped templates before treating reports as reconciled.

## Before production use

- Confirm the API `/health` endpoint returns HTTP 200.
- Confirm the API logs show successful Alembic migration and database connection.
- Confirm the first administrator can sign in.
- Confirm the frontend can call the API without CORS errors.
- Configure Dropbox credentials and verify a manual sync.
- Verify the scheduled job runs after 15 minutes and that pending imports drain over successive batches.
- Import existing historical database data only after verifying the backup and the destination schema. The Blueprint creates a fresh Render database; it does not copy a local database dump automatically.
- Configure a database backup/restore procedure before relying on the service for business-critical records.
